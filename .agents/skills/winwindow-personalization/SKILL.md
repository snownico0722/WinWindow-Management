# WinWindow personalization

1. Read `layout-guide.md` from the export. List the recording sessions, the dates covered, and which streams exist. Ask for optional app labels only if they materially change the result. Use session, segment and tick to order behavior. Use session and request ID to bind layout plans and corrections.
2. Keep complete sessions or days apart for discovery and validation. For every candidate give the conditions visible at decision time, supporting episodes, counterexamples, and the results on the held-out data. Keep missing behavior, sampled gaps, and ambiguous identity unknown. Treat `Cause: winwindow` as the application's action. Treat `Cause: observed` as a window state change with unknown origin. Reappearing immediately, an active workflow, and leaving a window available are evidence against automatic dismissal.
3. Write a layout candidate to `compiled-rules.json` using the schema in the guide. Favor recurring left/right, width, overlap, and companion relations supported by stable manual adjustments. Validate with `dotnet run --project tests/LayoutModel -c Release -- recordings.zip compiled-rules.json [session]`. Evaluate position and width corrections, protected regions and cases where the baseline was closer.
4. Write a behavior candidate to `behavior-rules.json` using the schema in the guide. Model a visit to a helper window, a specific next task where observed, and a dismissal after a measured wait. Suggest minimize if continued background work matters. Propose close only when the user repeatedly allowed the helper to disappear after the same handoff. A process already running before the helper visit contradicts a fresh-launch rule. Give each rule a stable ID and a concise name. Run `dotnet run --project tests/LayoutModel -c Release -- --behavior recordings.zip behavior-rules.json [session]` for the held-out session or repeat for each held-out session. Reports distinguish observed matching dismissals, fast returns, excess actions, and truncated follow-up.
5. Return the candidate JSON files, a short explanation of the evidence, and material validation gaps. Say when local replay was unavailable. In WinWindow the placement rules and continuous behavior rules have separate import buttons. Imported behavior rules run only after the user enables the individual rule.
