# WinWindow Management

C# / WPF / .NET 10 窗口管理工具，采用低饱和暖灰石与纯白卡片视觉。默认 580×500 DIP（最小 500×380），可自由缩放、最大化；每个管理对象的操作直接聚合在同一行卡片中，悬浮胶囊小窗为可选驻留入口。

## 使用

日常测试和预发布版使用标准可执行文件 `WinWindow-win-x64.exe`。安装 **.NET 10 Desktop Runtime x64（Windows 桌面运行时）** 后直接运行，无需解压。正式版还提供 `WinWindow-win-x64-self-contained.exe`，内置运行时，适合没有安装 .NET 的电脑。[下载 .NET 10](https://dotnet.microsoft.com/download/dotnet/10.0)

在 GitHub Releases 下载独立 EXE 和许可证文件。自动化测试与打包日志可在 GitHub Actions 对应运行记录中查看。

点击 **添加窗口**，选择目标即可加入管理。要同时置顶，可点候选行的 **添加并置顶**，或从 **拖拽置顶** 拖到目标。拖动时目标会出现描边，松开后短暂闪示；按 Esc 可取消。用筛选按钮或 Ctrl+F 搜索已管理的窗口。

每张卡片提供后台保持、窗口静音、置顶、鼠标穿透、收起／恢复和不透明度调整。滑块取得焦点后可用滚轮微调，点击百分比可输入精确值。低于 15% 时，卡片提供开启穿透的捷径。点击标题唤回窗口，行尾 × 移出管理，置顶、静音、调整透明度或开启穿透时会自动记住该窗口。右键可取消记忆或恢复原样。重启后，每条保存记录只恢复一个匹配的窗口，同名窗口逐个分配。托盘可添加窗口、全部取消置顶，也可在「管理的窗口」中逐个切换置顶。卡片优先显示窗口自己的图标。提示音和系统通知可在常规设置中切换。界面语言默认跟随系统，可在同一页切换简体中文或 English，即时应用到工作台、托盘和整理结果。

点击左上角 WinWindow 可收起为 188×36 的小窗，支持拖拽置顶和整理桌面，再点一次恢复之前的尺寸。顶栏齿轮打开统一设置。快捷键可一次修改多项，点「应用」保存，按 Esc 还原当前输入框。

WinWindow 默认在启动时通过 Windows UAC 请求管理员权限。可以在「设置 → 常规」取消勾选「以管理员权限启动」，下次启动生效。取消 Windows 权限确认时，本次以普通权限继续启动。

| 快捷键 | 操作 |
|---|---|
| Win + Ctrl + Space | 显示主窗口，已在前台时收回托盘 |
| Win + Ctrl + T | 切换当前窗口置顶 |
| Win + Ctrl + M | 强制最小化 |
| Win + Ctrl + Shift + R | 恢复全部原始状态 |
| Win + Ctrl + OemPlus / OemMinus | 增加 / 降低不透明度 |

配置位于 `%LOCALAPPDATA%\WinWindow-Management`。`--dev` 使用独立目录和单实例锁，测试可配合 `--data-dir <隔离目录>`。

“全部取消置顶”保留列表和其他设置；“恢复全部原样”撤销管理修改。真正退出最多等待 900ms 的恢复工作，未完成记录保留在 `recovery.json`，下次启动继续恢复，不因其他程序卡住而锁住退出。

## 桌面整理与游戏后台保持

单击主界面底栏 **整理桌面**，或在胶囊与托盘中选择同名命令。旁边的 **撤销整理** 可以还原上一轮调整。手动智能整理和自动档都会分析普通窗口的遮挡与操作区，包括被其他普通窗口完全盖住的窗口。首次使用即可根据当前任务估算主窗的阅读尺寸、参考内容的可见范围和返回上一个窗口所需的入口。Smart 会一起计算窗口的移动与缩放，也会参考已启用的个人摆放习惯。已置顶、穿透、最大化和全屏窗口保留位置。

在「设置 → 桌面整理」中选择 Smart 强度。**保守**以局部对齐、回屏和露出标题栏为主，尽量保持窗口尺寸。**平衡**会重排相邻或共同使用的一组窗口，比较并排、分行和允许部分遮挡的布局。**积极**还会在整块显示器上比较布局，并在空间紧张时按各窗口的尺寸限制分配空间。

从一个窗口连续打开几层内容时，Smart 结合新窗口的出现、前台顺序、点击来源和窗口归属识别这次导航。自动整理会等打开动作稳定，再给当前阅读窗口安排空间，上一级保留返回入口。近期来回操作同一组窗口时，会增加参考内容的可见范围。启用「智能整理时参考已记录习惯」后，多次独立的手动调整可以影响窗口的方向、宽度和副窗留出的区域。横向拥挤时，媒体副窗也会尝试边缘重叠；持续变化的监看小角会尽量留在原位。记录器默认暂停，画面变化采样可单独开启。导出的 ZIP 可供离线分析。详见[布局记录与回放](docs/LAYOUT_RECORDING.md)。

从左侧或右侧工作面打开新窗，Smart 优先在原侧继续阅读，小窗可就地放大。对侧空着也可以保留叠放。手动拖向另一侧、明确并排，或有两扇窗确实在共同使用的证据时，Smart 才重新比较跨栏方案。明显拖回一侧后，接下来的焦点切换和邻窗变化会保留刚选的方向。恢复已用过的窗口时，Smart 优先参考它在同一显示器上最小化前的工作位置。换屏或手动换边后重新判断。两扇已经居中叠放的窗口仅切换前台时，优先保留叠放。两窗已分居左右时，可在原来的一侧重新分宽。连续打开关联内容和短时间来回切换沿用原有的阅读位置。记录开启时，可在快照中查看这类切换到首次提交窗口位置的耗时。

读写文字时，自动整理会保护当前前台视图的位置、大小和已露出的内容，优先调整其他窗口。QQ、微信、Word、Excel、PowerPoint 和 WPS 的常用聊天或编辑界面参与识别，其他程序也可以通过前台文字插入点获得保护。用户自己拖动或缩放时，程序可提前计算，在松手后辅助一次。

Chrome、Edge 等 Chromium 浏览器可直接提供页面身份、可见文字区域和编辑焦点。可选的 [WinWindow 浏览器扩展](docs/BROWSER_EXTENSION.md) 还能区分同地址的多个标签页，识别被放在后台的浏览器窗口里的静音播放，并把正文列或播放器的范围用于整理。网页内的区域识别按站点授权。

底栏「整个桌面」旁可以直接选择 **关闭、轻度、完整**。关闭后仍可手动整理和撤销。轻度会在拖动或缩放松手后辅助刚操作的窗口，也会在独立的新任务窗口首次打开、且还未接收输入时，调整该窗的位置或大小。完整允许根据窗口开关、焦点或布局变化整理工作区。整理幅度决定每档权限内采用哪些调整。旧设置继续沿用原授权。原「轻度」及「完整辅助」仍只响应松手，显示在轻度选项下。显式重新选择轻度可启用单窗开窗辅助。原「自动」对应完整。打字、点击正文或滚动页面时可以继续使用当前摆法。刚把窗口从系统安排的位置拖回来，程序会记住你修正了哪一轴。短时间内连续两次拖回，后续自动整理会避开该轴被反复拒绝的方向。开启摆放习惯后，程序约每十分钟在后台回放近期回拖，比较哪种调整能少一次补摆。结果等下一次真实整理时使用。选择立即生效，下次启动沿用。顶栏设置中的 **桌面整理** 可调整算法和观看偏好。**快捷键** 可批量编辑、交换后应用。**数据与记录** 可以启停、导出和清空本机布局记录。默认手动整理，记录器默认暂停。原有整理参数沿用当前 WinWindow 数据目录的 `Layout`。

Smart v3.1 在双窗任务意图不明确时，同时比较并读和交替查看。多扇横向阅读窗可以按原左右顺序让位。摆放学习 v2.8 会根据后续手动补摆，逐轴比较各算法当时提出的方案。相近且已值得执行的方案可以因此改变排序。打字、静置或信誉更新都不会触发整理。

Smart v3.0 会先判断两扇窗是否要并读、轮流查看，或只需保留可见的参照。并读时可以只沿水平方向让位，保持原来的高度和阅读行位置。个人规则 v7 可以按这一次的前台和后台用途指定上述意图。设置中的摆放学习模型仍是 v2.7。

Smart v2.9 会从多次独立手动调整中学习位置和大小的可接受范围。已有窗口处于惯用范围内时，个人偏好本身不会推动它向某个历史坐标靠拢。

Smart v2.8 会在双窗并看时比较只移动一扇窗的让位方案。个人规则 v6 可按阅读、编辑或播放用途指定同一应用的不同窗口。

完整模式下，Smart v2.7 可以在拖动已有双栏内边缘后同步调整搭档，保留两侧外边缘；普通自动整理也会逐轴比较额外移动的收益。摆放学习 v2.5 可按已观测到的用途区分同应用的多个实例。

Smart v2.6 会结合右键落点、宿主和窗口边框识别临时菜单。后台参考窗最近收到滚轮、前台插入点正在移动时，求解器会提高搬动相应窗口的代价。本机摆放学习 v2.4 可分别记住阅读前台文档和滚动后台参考窗时的手动摆法。本地快照与长期记录保留当时可取得的窗口标题、类名、句柄、进程路径和指针位置；整理决定可以追到调度器观察到的具体变化。

底栏「当前快照」会在桌面依次写入「第一版.zip」「第二版.zip」等快照，包含点击后约 10 秒的窗口状态和整理决策。「数据与记录」里的「快照追溯记录」默认开启，另外把过去最多 5 分钟的窗口状态、整理决策和拖动手势写进同一个 ZIP。长期记录暂停时仍可追溯，数据平时只保留在内存中，关闭追溯时清空。「行为学习摆放」可分别启用本机摆放习惯和导入规则。完整和手动 Smart 会检查长期静置的窗口。如果收起一扇窗能为当前任务腾出可见区域，可以将它最小化，并通过「撤销整理」找回。「行为学习」可从重复的任务交接中发现收起或关闭窗口的候选，由用户逐条开启，完整模式下才自动执行。关闭通过应用自己的正常关闭流程执行。

在游戏所在行打开 **后台保持**，默认使用不注入目标进程的温和激活通知；若单机游戏仍因焦点查询或锁鼠暂停，可在「设置 → 常规」中开启 **启用增强注入模式**。这个全局开关同时切换所有已开启后台保持的窗口，关闭后统一恢复温和模式。增强模式下还可按需勾选 **失焦时锁定窗口内光标坐标** 防止边缘滚屏。增强模式在目标内拦截失焦消息、焦点查询、`ClipCursor`/`SetCursorPos` 锁鼠及后台按键轮询，真实前台时原样透传子窗口焦点。同行的 **窗口静音** 可直接静默目标应用音频，关闭开关、恢复原样、移出或退出时还原。

## 构建与验证

```powershell
dotnet build src/WinWindow/WinWindow.csproj -c Release
dotnet run --project src/WinWindow/WinWindow.csproj -- --dev
dotnet run --no-build -c Release --project src/WinWindow -- --self-test TestResults
./scripts/package.ps1
```

打包原生组件需要 CMake 3.24 或更高版本，以及 Visual Studio 的「使用 C++ 的桌面开发」、x86/x64 工具和 Windows SDK。构建直接使用仓库内的 NoFocusLoss 与 MinHook 源码。运行 `./scripts/package.ps1 -TestNative` 可以分别验证 32 位和 64 位测试窗口的失焦消息、焦点查询、后台鼠标及卸载恢复行为。

默认打包命令在 `artifacts/` 生成标准版 EXE 和许可证文件；使用 `./scripts/package.ps1 -IncludeRuntime` 时同时生成自包含版 EXE。打包脚本与 GitHub Actions 工作流均不生成 ZIP 压缩包或压缩制品。正式发版时，测试通过后工作流直接将 EXE 与许可证文件附加到 GitHub Release。手动运行 Actions 时，也可以填写已有 Release Tag 来更新对应版本的下载附件。

自动测试使用真实 WinForms/WPF 目标及完整主程序，验证原生状态、行内操作、收起/恢复、悬浮胶囊、失焦退让、单实例唤醒、阻塞目标下的退出及恢复日志，并输出实际界面截图。

## 边界与结构

0.1.1 正式版。已通过仓库自动化与打包回归，但不代表所有游戏或硬件的兼容认证。强制最小化只执行一次有限流程，必要时隐藏，不持续压后台，不注入。最小化/隐藏不保证游戏继续渲染或挂机。跨权限与混合 DPI 人工验收见 [MANUAL_TESTS.md](docs/MANUAL_TESTS.md)。

`Native` 封装 Win32 与图标缓存；`WindowManager` 管理操作与恢复；`WindowRow` 维护单行卡片交互与编辑状态；`DesktopIntegration` 管理托盘、快捷键和唤醒；`StateStore` 负责持久化。外部窗口修改不在 UI 线程同步等待。

产品决定见 [DECISIONS.md](docs/DECISIONS.md)，维护规则见 [AGENTS.md](AGENTS.md)。布局程序集沿用 NeatWin 源码，不预建插件平台或数据库，尚未选择开源许可证。

Smart v2.0 支持按应用组合和触发方式导入个人模型。它可以改变重排成本、尺寸策略与参照内容的可见范围，并区分应用内临时卡片和独立工作窗口。录制 ZIP 附带可直接运行的分析工具和个性化迭代说明，支持对比默认与个人规则的回放结果。参见[布局记录与回放](docs/LAYOUT_RECORDING.md)。

Smart v2.5 会保留已经核实、仍然可读的工作窗口布局。在这些窗口之间切换会更新当前焦点。出现新遮挡、拖动窗口或主动点击整理时，程序可以立即重新排布。浏览器去黑边会同时检查暗带边界和候选画面内部的运动，首次遇到静止画面时暂时保留窗口尺寸。

Smart v2.4 将当前可读空间的收益与窗口跳动、文字换行、刚刚摆过又被挪动的成本一起比较。手摆松手和首次开窗可以顺势微调，同一变化发生在读写期间会更谨慎。摆放学习 v2.3 能在同一应用组合中分别学习对照、文字输入界面和有播放证据时的位置与尺寸。
