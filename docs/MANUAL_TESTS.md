# Windows 实机验收

自动检查使用真实 WinForms / WPF 目标及完整主程序；不是所有游戏或硬件的兼容认证。

| 场景 | 应验证的行为 |
|---|---|
| 全屏 / 无边框游戏 | 强制最小化显示真实状态；失败则隐藏；打开其他应用不因“显示桌面”解除而带回游戏。后台帧率和挂机单独记录。 |
| 0% + 穿透 + 防呆 | 低于 15% 未开穿透时出现「启用鼠标穿透」，点击即开启穿透；0% 后列表/托盘/恢复快捷键仍可找回。 |
| 屏幕空间高亮 | 浏览卡片时桌面保持原样；拖拽时移动或缩放目标，描边随目标更新；按 Esc、松开或失去捕获后取消预览。置顶后短暂闪示，键盘焦点保留。 |
| 同名窗口与图标 | 候选与管理列表均显示原生应用图标；多个路径/类/标题相同目标不随机匹配，已关闭 HWND 不复用到新进程。 |
| 权限 | 普通实例操作提权目标失败有真实反馈；普通第二次启动能唤醒管理员实例，不自动提权。 |
| 混合 DPI | 100%、150%、200% 跨屏拖动、最大化、收起/展开及屏幕高亮框定位准确。 |
| 焦点与唤醒 | 切到普通窗口后退到其后；托盘、快捷键、第二次启动可唤回；焦点策略关闭时不残留临时 TOPMOST。 |
| 悬浮胶囊手势 | 左上角徽标名称点击收成 188×36 悬浮胶囊（显示计数并支持拖拽置顶与整理桌面），再点展开；拖动只移动，恢复尺寸与置顶选择。 |
| 行内直接操作 | 图标、图钉、穿透、滑块（仅在滑块取得焦点后滚轮微调）、点击编辑百分比、收起按钮不误触标题唤醒；标题单击不改变已最大化目标尺寸。 |
| 取消与移出 | 单行/全部取消置顶不删列表、不重置透明度；× 取消置顶并移出，不关闭目标，即使它原本置顶。 |
| 添加与拖拽 | 选择器搜索/Enter/Esc/点外关闭；按住拖拽到目标只置顶，单击未拖动给出提示；Esc 可取消拖动。 |
| 多行透明度 | 连续拖动不中断；正在输入的文字不被旧结果覆盖；切换行或滚动复用后不串目标；0% 不被夹值。 |
| 快捷键 | 可交换两个已注册的组合后一次应用；冲突保留原绑定，Backspace/Delete 清空，Esc 还原当前项。 |
| 关闭与退出 | 应用托盘图标正常显示；按设置藏托盘或退出；退出不被单个目标卡住；未完成记录保留，下一次恢复。 |
| 界面 | 默认 580×500、最小 500×380；宽窄之间切换时后台保持文字随行宽变化；搜索框取得焦点后，选中卡片的描边仍可见。深浅色各验一次。 |

```powershell
dotnet build src/WinWindow/WinWindow.csproj -c Release
dotnet run --no-build -c Release --project src/WinWindow -- --self-test TestResults
dotnet run --project src/WinWindow/WinWindow.csproj -- --dev
```

开发模式独立状态目录和单实例锁，快捷键仍为系统资源。测试进程仅结束自己启动的子进程，不触碰用户现有的管理器实例。

## 桌面整理与后台保持

1. 在同一显示器打开两个有重叠的普通窗口，点底栏“整理桌面”，再点旁边的“撤销整理”。检查实际移动和撤销的位置、前后层级，并确认已置顶的第三个窗口保留位置。手动再拖动一个窗口后撤销，核对状态提示。
2. 在主界面底栏依次点击手动、轻度、完整、自动，核对选中状态；在最小窗口尺寸检查四个档位和整理、撤销都能点击。完全退出并重新打开 WinWindow，检查原档位恢复。仅手动模式下启动不应触发整理。最小化到托盘时也能整理、撤销。
3. 打开“设置 → 数据与记录”，默认暂停。开始记录后移动窗口，检查记录计数、导出、暂停和重启后的状态。开发模式写入独立的数据目录。
4. 从“添加窗口”点游戏名称，确认只生成管理行，游戏维持原先置顶状态。开启该行的“后台保持”，切到另一个应用检查实际暂停或音频行为以及键盘输入归属。关闭开关、移出目标和退出 WinWindow 分别检查游戏恢复正常失焦行为。记录实际游戏、窗口模式和支持程度。
