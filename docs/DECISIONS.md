# 产品与实现决定

## 2026-11-10 · 独立 WPF 重写

用户决定：用 C# / WPF / .NET 10 在 WinWindow-Management 实现独立 Windows 窗口管理系统，采用 PaperTodo 视觉，取消透明度下限，加入强制最小化，主界面不能局促。

- 默认 1180×760 DIP，最小 880×560，可最大化，无最大尺寸限制。小窗仅为可选入口，展开保留原尺寸、最大化和长期置顶选择。
- 不透明度 0–100%。完全透明或隐藏后仍能由列表、托盘和恢复快捷键找回。
- 强制最小化只执行一轮：记录 WINDOWPLACEMENT → 异步请求 → 验证真实状态 → 必要时隐藏。不持续压后台，不注入游戏。
- 规则按程序路径、类和标题精确匹配；不唯一时不猜测，不把收起写成永久自动规则。
- JSON 保存设置与恢复记录；PID / 启动时间 / 窗口类验证身份，危险修改前落盘。正常退出保留用户规则。
- 不自动提权，不结束被管理进程；无法恢复的逐像素透明目标只拒绝不透明度修改。
- 不预建插件平台、布局引擎、工作区编排或数据库。

## 2026-11-10 · 可靠性整改

本体层级使用原生非激活路径，不混写 WPF Topmost。失焦取消临时置顶并让到新前台之后；只有主动唤醒请求激活，临时抬层在 finally 立即收尾。

外部窗口同步修改在工作线程执行，同一目标仅一个在途修改，不影响主窗口和其他目标。真正退出尽力恢复，最多等待 900ms，不因单个目标失败而拒绝退出；未完成的恢复日志保留，下次继续，不假报成功。

跨权限仅放行无参数 Show 消息，发送方检查结果；托盘启动使用 EnsureHandle，不再先显示再隐藏。原先的两栏检查器布局在下一节交互重做中替代。

## 2026-11-10 · 参考用户的 Pin-It / PaperTodo 交互重做

用户本轮要求：参考自己定义的 Pin-It 交互，以及 PaperTodo 的交互优化来改。不是只删装饰或沿用上轮 Agent 的两栏检查器方案。

参考来源：用户已定义的 Pin-It 品牌点击收起、中央拖动区不触发收起、本体图钉与对象图钉分离、选择/拖动置顶分离、取消置顶与移出分离；PaperTodo 的对象内直接操作、收起/展开延续同一对象、次要操作依附右键菜单与既有控件。本节是据此落实到 WinWindow 的实现选择，不把所有细节追认为用户逐项指定。

- 主列表只展示已经加入及等待中的对象。置顶、穿透、0–100% 不透明度、收起/恢复、移出位于同一行，不先选择再转去右侧操作区。
- “置顶窗口”打开可搜索选择器，“拖动置顶”单独拖到目标；重复添加只置顶，不取消或重复建行。
- 行内图钉和“全部取消置顶”保留管理列表及透明度、穿透；× 取消置顶并移出，恢复其他改动，不关闭目标程序。原本置顶的目标也不会被 × 再次恢复成置顶。
- 标题单击唤回对象；已经可见/最大化的对象不因此还原尺寸。收起与恢复共用一个随真实状态变化的按钮。
- 列表归属独立于置顶和恢复快照；“恢复原样”保留这一行，“移出”才删除归属。
- 左上角品牌点击收起/展开，拖动只移动；中间标题栏只拖动。小窗是同一窗口的折叠入口，不另造带“打开/恢复全部”的小面板。
- 记住设置、恢复原样、复制信息使用行右键菜单。状态提示不挤动布局；不为每项能力添加长期说明与确认层。
- 行控件维护自己的编辑状态。值变化不重建列表，透明度连续输入合并为最新值，不覆盖正在输入的文字，不因切换行把值写到另一个对象。
- 设置中的关闭选项直接写“关闭时退出程序”，对应原 CloseToTray 的反向显示，保持既有默认行为。

保留可靠性整改，不重开技术选型。真实全屏游戏、跨权限桌面和混合 DPI 仍按 MANUAL_TESTS.md 人工验收，未覆盖的测试不宣称已完成。

## 2026-11-19 · 桌面整理与后台保持

- 主界面“整理桌面”和托盘命令共用 NeatWin 的布局引擎。源自 snownico0722/NeatWin 的 bf2e9dc128ac84312317d017bbd7d3c55055c914，编译成随主程序发布的程序集。整理使用独立 STA 消息循环，WinWindow 持有唯一的托盘和全局快捷键入口。
- 默认手动整理，记录器默认暂停。启用自动模式或记录后，下次启动恢复该选择。整理设置与记录位于 WinWindow 数据目录下的 Layout，开发模式与正式模式独立。
- 置顶、鼠标穿透、最大化和占满显示器的窗口保留位置；完全透明、隐藏和最小化的窗口不参与可见面积计算。整理的撤销使用 NeatWin 的会话内位置与层级记录。
- 用户要求统一设置与交互。参考 PaperTodo 的设置侧栏，将常规、桌面整理、快捷键、数据与记录放入同一主窗口。页面本地滚动，常规修改即时生效。整理与撤销并列，有可撤销的调整后才启用撤销。
- “添加窗口”只加入管理，可在候选行显式置顶。后台保持在目标窗口行启停，默认采用不注入的窗口激活通知；常规设置提供可选的增强注入与失焦光标坐标锁定，按目标 32/64 位架构加载 NoFocusLoss 原生组件拦截失焦消息、焦点查询、锁鼠与按键轮询（真实前台原样透传子窗口焦点），并在关闭、恢复、移出与退出时卸载还原。窗口静音按进程管理 WASAPI 会话，同一进程的各窗口同步显示。恢复时逐个还原被修改会话的原始状态。

## 2026-11-19 · 紧凑工作台

- 新配置的主窗口默认 580×500 DIP，最小 500×380。已有配置沿用保存的尺寸和位置。底栏并列整理和撤销，窗口卡片保留选中描边，空间充足时显示「后台保持」文字。
- 应用图标按需读取。百分比可点击编辑，选中滑块后才用滚轮微调。接近透明时可从当前卡片开启穿透。
- 拖拽选择目标期间跟踪窗口边界，置顶操作完成后短暂描边。浏览列表只显示卡片状态。胶囊提供拖拽置顶与整理桌面。
- 快捷键集中编辑后应用。录制已被 WinWindow 注册的组合时填入当前输入框，以便交换快捷键。

## 同名窗口与规则恢复

置顶、透明度和穿透按窗口自动记忆。多个同路径、同类名、同标题窗口按保存顺序各匹配一个活跃窗口，已有绑定优先。取消记忆后，本次管理期间继续调整不会重新创建该规则。已保存的后台保持规则也由行内开关的同一路径应用。同一进程只启用一个目标窗口。

## 智能整理决策

- 手动整理和自动档共用窗口可操作性、可读性和窗口关系分析。被普通窗口完全挡住的普通窗口也参与分析。手动点击会重新评分并降低采用改善方案的门槛。自动档等外部变化稳定后整理，并识别本轮整理产生的窗口事件。
- 窗口重叠同时支持共同阅读与轮换使用两种解释。可见标题栏、切换历史、媒体与用户习惯各自形成证据，只有明确任务关系才直接确定解释。评分同时考虑对两个解释都有影响的操作区。
- 保守优先修复局部问题，平衡比较相关窗口的大小和排列，积极比较整块显示器的布局。各档比较当前桌面与候选方案的实际收益。置顶、窗口尺寸下限、显示器工作区和受保护的内容区域参与可行性检查。

## 2026-11-21 · 启动权限

默认在启动时通过 Windows UAC 请求管理员权限，取代早期的启动权限策略。常规设置的「以管理员权限启动」可关闭，下次启动生效。取消 UAC 时以普通权限继续启动。已运行的实例仍通过专用 Show 消息唤醒。


## 基于注意力的 Smart 整理

默认以 16:9 为主要场景，21:9 复用相同的工作区和 DPI 计算。没有历史样本时，前台、短期输入和窗口归属就可以建立本轮任务。首次交接保留返回入口，反复对照时优先保障参考内容的可见范围。用户刚完成的拖动或缩放为周边窗口的调整提供锚点。

Smart 会一起尝试主窗扩容和周边窗口让位，优先补足主窗可读尺寸、关联窗口可见性及舒适尺寸，再比较移动和重排成本。几何动作之后验证实际落位。静置窗口在收起后能改善任务可见性时可被最小化，关闭动作由用户启用的规则触发。

## 居中、并排与浮动笔记

单独阅读时，求解器把内容放到当前工作区的水平中心，同时检查居中会遮掉多少仍可见的相邻窗口。两扇窗需要共同阅读时，求解器比较完整的左右摆法，优先使用外侧空位，拥挤时允许内侧边缘部分交叠。紧凑的编辑器叠在正在使用的窗口上时，可以作为浮动笔记。常用应用的角色只提供初始线索。两扇窗的默认空间分配使用可见区域、近期注意力、输入、实际尺寸约束及明确的个人偏好。前后台、可见性和输入相同的两个窗口，交换应用名称后仍得到相同的可读空间预算。

个人模型只学习用户调整过的维度。多次移动能建立方位偏好，反复缩放才能建立对应轴的尺寸偏好。相同任务中两种冲突的摆法各占一半时，求解器保留默认判断。回放用于复现问题，跨屏幕尺寸、DPI、任务角色、左右方向和未知应用的行为性质用于检验默认模型。

拖向左、右或中间时，轻度辅助可帮助对齐。完整辅助和自动档还会在松手后有限扩容，并重新计算周边窗口。桌面、任务栏或拖放操作取得输入时取消旧的自动整理。回到应用后根据新的焦点计算。

应用角色和回收分开判断。通用交接规则可根据重复出现的来源窗、后继任务和实际最小化或关闭行为提议回收。返回来源、切入无关任务或仅看见窗口隐藏，都不足以沿用上一轮关闭预测。

连续打开多层内容时，窗口创建和前台次序提供路径，点击或窗口归属可以佐证。自动整理让正在打开的下一层先取得焦点，再用阅读窗、直接前驱和更早的窗口分别求解。反复返回同一对窗口会重新建立对照证据。识别所需的信息来自顶层窗口事件。

评估整理方案时，同时检查主任务的可读面积、参考内容实际露出的区域、回到上一层的入口、用户后续手动摆放和显式撤销。换应用、交换主次、增减参考窗、镜像左右和改变 DPI，都能用相同指标检验。只有在有记录的真实使用中才统计实际手动操作次数。

## 文字与表格的视觉定位

用户读到的那一行、正在输入的消息和当前单元格都有屏幕位置。普通自动整理保护当前前台文字视图的坐标、尺寸和原有可见部分，优先通过调整邻窗改善桌面。用户自己拖动或缩放、或显式点击整理，是不同的意图；一次松手可以获得一次辅助。切换到其他任务后重新判断。媒体与游戏继续使用画面可见性、可用操作区和任务关系来分配空间。

常见聊天与办公程序按当前窗口表面识别。聊天、文档、表格和幻灯片编辑各有角色；放映、启动中心、文件选择器和独立网页分别按自己的证据判断。陌生应用的实际前台插入点也能提供文字输入证据。

手势进行时在后台准备候选位置。松手后优先核对当前目标、焦点、显示器及邻窗，过期的候选即时回退。几何提交先于可选的诊断比较。松手路径跳过同步多帧视频检测，仍可复用近期几何一致的视口证据。

## Smart v1.5 · 什么可以触发窗口动作

目标是减少用户亲手摆窗口的次数，同时允许用户用后续自然行为推翻系统对当前布局的理解。一次点击、滚轮或阅读停留进入注意力历史。新开、恢复、焦点或可观测的桌面结构变化、手势松手和显式整理各自提供求解入口。一个手势只提交一次辅助，其位置回执由调度器吸收。导航仍等待连续打开动作稳定。

取代 v1.3/v1.4 的做法：普通指针交互曾在换目标和同目标交互满六秒时请求全局整理。原意是识别在后台参考窗上滚动和任务交接后的注意力变化。第六版回放显示，继续操作和空间问题可以完全无关。文章持续被阅读只能减弱对来源列表的返回需求。阅读中的文章和仍有用的后台视野各自需要独立的几何收益，时间到期没有动作授权。

默认模型先比较前台可读性、参考窗可达性及明确手势落点。在这些目标相同的候选之间，按意图来源调整跨过动作门槛所需的净收益。普通自动观察系数 0.35，新开或恢复等成员变化及确认的开窗碰撞 0.55，顺着实际松手落点 0.85，显式整理 1.00。这些系数是待校准的工程起点。通过同场景镜像、不同 DPI 与成对正反例检查它们，不能用动作总数衡量改进。

学习模型 v1.1 分别记录水平位置、宽和高的习惯可信度。如果用户从系统提交的位置往回拖，在同一组邻窗下按各轴的反向幅度修正当前判断。手势的四秒即时辅助期与这份情境证据分别管理。长期偏好仍需要独立的人工样本；自动吸附和没有撤销均不增加习惯票数。输入期间至提交前发生的新操作可以中止过期方案。以后由新的空间事件重估。

验收依据见 [布局经验](LAYOUT_CASES.md)。如果相同输入能稳定预测某种具体空间损失，应记录损失的位置、受影响对象及对照回放，再修订执行条件。
