# 产品与实现决定

## 2026-11-10 · 独立 WPF 重写

用户决定：用 C# / WPF / .NET 10 在 WinWindow-Management 实现独立 Windows 窗口管理系统，采用 PaperTodo 视觉，取消透明度下限，加入强制最小化，主界面不能局促。

- 默认 1180×760 DIP，最小 880×560，可最大化，无最大尺寸限制。小窗仅为可选入口，展开保留原尺寸、最大化和长期置顶选择。
- 不透明度 0–100%。完全透明或隐藏后仍能由列表、托盘和恢复快捷键找回。
- 强制最小化只执行一轮：记录 WINDOWPLACEMENT → 异步请求 → 验证真实状态 → 必要时隐藏。不持续压后台，不注入游戏。
- 规则按程序路径、类和标题精确匹配；不唯一时不猜测，不把收起写成永久自动规则。
- JSON 保存设置与恢复记录；PID / 启动时间 / 窗口类验证身份，危险修改前落盘。正常退出保留用户规则。
- 不自动提权，不结束被管理进程；无法恢复的逐像素透明目标只拒绝不透明度修改。
- 不预建插件平台、布局引擎、工作区编排或数据库。

## 2026-11-10 · 可靠性整改

本体层级使用原生非激活路径，不混写 WPF Topmost。失焦取消临时置顶并让到新前台之后；只有主动唤醒请求激活，临时抬层在 finally 立即收尾。

外部窗口同步修改在工作线程执行，同一目标仅一个在途修改，不影响主窗口和其他目标。真正退出尽力恢复，最多等待 900ms，不因单个目标失败而拒绝退出；未完成的恢复日志保留，下次继续，不假报成功。

跨权限仅放行无参数 Show 消息，发送方检查结果；托盘启动使用 EnsureHandle，不再先显示再隐藏。原先的两栏检查器布局在下一节交互重做中替代。

## 2026-11-10 · 参考用户的 Pin-It / PaperTodo 交互重做

用户本轮要求：参考自己定义的 Pin-It 交互，以及 PaperTodo 的交互优化来改。不是只删装饰或沿用上轮 Agent 的两栏检查器方案。

参考来源：用户已定义的 Pin-It 品牌点击收起、中央拖动区不触发收起、本体图钉与对象图钉分离、选择/拖动置顶分离、取消置顶与移出分离；PaperTodo 的对象内直接操作、收起/展开延续同一对象、次要操作依附右键菜单与既有控件。本节是据此落实到 WinWindow 的实现选择，不把所有细节追认为用户逐项指定。

- 主列表只展示已经加入及等待中的对象。置顶、穿透、0–100% 不透明度、收起/恢复、移出位于同一行，不先选择再转去右侧操作区。
- “置顶窗口”打开可搜索选择器，“拖动置顶”单独拖到目标；重复添加只置顶，不取消或重复建行。
- 行内图钉和“全部取消置顶”保留管理列表及透明度、穿透；× 取消置顶并移出，恢复其他改动，不关闭目标程序。原本置顶的目标也不会被 × 再次恢复成置顶。
- 标题单击唤回对象；已经可见/最大化的对象不因此还原尺寸。收起与恢复共用一个随真实状态变化的按钮。
- 列表归属独立于置顶和恢复快照；“恢复原样”保留这一行，“移出”才删除归属。
- 左上角品牌点击收起/展开，拖动只移动；中间标题栏只拖动。小窗是同一窗口的折叠入口，不另造带“打开/恢复全部”的小面板。
- 记住设置、恢复原样、复制信息使用行右键菜单。状态提示不挤动布局；不为每项能力添加长期说明与确认层。
- 行控件维护自己的编辑状态。值变化不重建列表，透明度连续输入合并为最新值，不覆盖正在输入的文字，不因切换行把值写到另一个对象。
- 设置中的关闭选项直接写“关闭时退出程序”，对应原 CloseToTray 的反向显示，保持既有默认行为。

保留可靠性整改，不重开技术选型。真实全屏游戏、跨权限桌面和混合 DPI 仍按 MANUAL_TESTS.md 人工验收，未覆盖的测试不宣称已完成。
